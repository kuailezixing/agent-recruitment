# 问题
1、messages传参时数据结构是列表，内容是字典形式存在的{'role':'user','content':'用户问题'},{'role':'system','content':'助手'}
2、agent使用的是langchain框架时，API调用使用from langchain_openai import ChatOpenAI,自定义agent使用from openai import OpenAI,前者是一个langchain封装好的模拟客户端，后者是一个官方提供的原生客户端
3、langchain框架创建agent使用create_agent，自定义agent使用OpenAI()创建的实例的方法 .chat.completions.create()
4、langchain创建agent时，必备传入参数model,system_prompt,tools
5、agent调用工具时，create_agent的参数tools的值是一个列表，列表中的元素是使用@tool装饰器装饰的自定义函数
6、create_agent返回的agent应用，调用方法invoke启动agent,提取返回的信息时需要注意信息所在的索引位置。
7、agent会根据用户的问题，选择对应的tool生成答案，没有相应的tool时，agent无法回答。
8、agent返回的输出内容，可以通过prompt提示词限定输出内容，例如格式化输出(只输出json格式，前后不加任何解释说明)，对于不希望出现的回复，在提示词里禁止掉，提示词越明确，大模型越遵守(因为大模型本质是概率引导)
9、agent首先是大脑，拥有丰富的知识储备，其次是工具的使用者
10、多工具调用时，如果函数说明不够清晰，则大模型在判断工具是否调用时，可能会直接调用输出结果的工具，而忽略掉中间量输出的工具调用，如查询某城市天气情况，输出城市天气情况的是get_weather，但它需要地理位置信息，所以需要先通过get_city_location获取城市的地理位置信息。
11、@tool装饰器装饰的函数，返回的内容，可能不会完整的传递给下一个tool，LLM会根据下一个tool的参数名称和函数的注释文档来猜测需要哪些内容(Langchain会将函数的签名和函数说明打包发送给LLM)，从而选择性的提取上个tool返回的内容，这时候需要在下一个tool的注释文档中清楚的说明参数的含义，包含了哪些内容
12、使用openai原始方法实现ReAct时，首先传递给模型消息和工具列表，模型返回tool_calls需要调用的工具，然后手动调用工具得到工具执行的结果，重新添加到大模型的消息列表中{'role':'tool','content':tool执行的结果,'tool_call_id':tool_calls.id}，但在这之前，需要给消息添加一条消息{'role':'assistant','content':None,'tool_calls':tool_calls}，告诉大模型，工具执行的结果是依据此处。另外messages列表中的顺序要按照'role'是system，user,assistant,tool这样的排序，system必须在第一位,tool必须跟在assistant后面
13、向量检索中计算向量相似度的方法主流有三种：余弦相似度（语义/文本），点积（推荐系统），欧式距离（图像特征/空间）。
14、2-step RAG 运行步骤：嵌入模型将文档转数值向量，进行向量存储，用户问题，检索文档，生成答案，向用户返回答案
15、Agentic RAG 运行步骤：嵌入模型将文档转数值向量，进行向量存储，用户问题，大模型(LLM)思考是否查询知识库，怎么查询，提示词是否优化，然后行动：调用工具查询，观察返回的结果是否满足用户问题，不满足时再思考-行动-观察，反思：结果满足用户问题后，大模型生成答案给用户。
16、RAG向量检索时，余弦相似度检索使用的是语义检索，日期/数字类的语义检索的权重很很低，导致检索结果不准确，需要通过混合RAG：密集检索（向量，语义检索）+稀疏检索（关键词检索），各取top N结果，通过RRF（倒数排名融合）算法将两边的分数重新排序。
17、大模型如果该调用工具时，没有调用，可能是工具的描述不够准确。
18、如果RAG检索结果不符合预期，语义权重过高导致时，可以采用预过滤（Pre-filtering）
19、隐藏小bug：局部(某些时候先运行)定义的变量如果也出现在其他模块里，需要定义成全局变量
20、agent定义的工具需要单独放在一个py文件里，也就是工程化管理，每个文件负责特定的处理逻辑，当然也包括其他代码，例如配置文件
21、agent通用架构：用户query,约束提取器，元数据过滤器，向量检索，精排，结果组装，返回给大模型。
22、知识库切分策略：1、固定token数分块，常用于验证原型流程。2、结构感知分块，通过文章的标题，编号等结构分块。3、语义分块，通过embedding，在语义突变时分块。4、递归分块，按段落，句子，词的优先级递归分块，尽量保持语义边界，这也是业界默认使用的策略。
23、python文件被导入其他文件时，尽量不要使用from import *,要明确表明import哪个变量。而且不要依赖导入时自带的包(隐式依赖，有潜在bug风险)，应该在本文件内重新导入包
24、json schema 的字符串类型只认string,不认str
25、函数参数传参时，名称尽量和参数名保持一致，不容易混乱
26、字符串里添加变量引用时，格式使用：f"格式是使用大括号{这里是变量名}"，外侧尽量使用双引号
27、评估RAG的两个指标：Hit@3(hit rate at 3)前3名命中率,MRR(mean reciprocal rank)平均倒数排名。作用是Hit@3评估RAG检索的召回能力，即用户每次提问，RAG返回的排名前3条记录里都有我们希望出现的关键词，Hit@3=命中的总次数/提问的总次数；MRR是评估RAG检索的排序质量，即用户每次提问，RAG返回的前3条记录中，我们希望出现的关键词所在的记录排在第几名，排名越靠前，RAG的排序质量越好，MRR值越高，MRR=sum(1/每次的rank)，这里的rank从1开始，如果是按照记录的索引计算时，MRR=sum(1/(每次的索引+1))，因为索引是从0开始的。当前Hit@3=0.917,MRR=0.917。测试集是12条记录
28、Reranker（精排-重排序）的原理：是将用户的query和文档一起打包发给模型，计算相关性分数，是细粒度的比较（逐词逐token交互比对），且信息无损。比向量检索的粗粒度的只比较向量方向，且信息有损的计算相似度更精确
29、BM25检索的原理：是利用jieba对文档切词，对切词后的语料库通过BM25Okapi建立BM25索引，用户提问后，对query切词，计算query切词后的语料库在BM25索引上的得分，返回前10
30、API调用：工具API调用和大模型API调用的区别是，前者返回现成的json格式的结果，后者返回大模型推理过程内容。
31、Chain-of-Throught(CoT)思维链：大模型分步推理。第1步做什么，第2步做什么。。。，可以让大模型静默执行，也可以让大模型展示在输出页面上，亦或是添加在最终结果里
32、Function Calling(函数调用)：原理是将定义的Json Schema(tools的定义)发给大模型作为工具使用说明书，说明越详细，大模型调用越准确。
33、大模型思考用户问题后，返回的推理过程内容，底层需要在messages里添加'assistant'角色，因为是大模型推理过程，所以'content'是None，并且需要附带'tool_calls'，表明需要调用的是哪个工具。
34、redis启动（docker方式）：docker run -d --name redis -p 6379:6379 redis:7-alpine，docker run用镜像创建容器并启动，-d（detached）后台运行,--name redis给容器起名为redis，-p 6379:6379把容器的6379端口映射到主机的6379端口，redis:7-alpine用哪个镜像（Images里有的）
35、redis停止（docker方式）：docker stop redis
36、直连redis（docker方式）：docker exec -it redis:redis-cli
37、redis的好处：使用redis存储会话信息，可以保证服务重启时会话信息不丢失，用户接着提问，大模型能接住
38、json.dumps()只能序列化基础类型（dict,list,str,int,float,bool,None），大模型返回的tool_calls是ChatCompletionMessageFunctionToolCall对象，不是json原生类型。
39、SDK和API的区别：SDK就是将API调用封装在库里，然后SDK是通过调用这个库实现API调用
40、docker里redis已经断开，但还是能用redis：有其他redis也在运行。排查思路：1、Test-NetConnection -ComputerName localhost -Port 6379测试redis端口是否断开，返回的TcpTestSucceeded为False则断开了，True则还没断开。2、netstat -ano | Select-String ":6379"找到占用端口的PID。3、Get-Process -Id <PID>根据PID找到进程名。4、Stop-Process -Id <PID> -Force杀掉进程名。5、重新执行第1步。6、sc.exe stop Memurai管理员模式停止进程名
41、docker desktop页面，Images是创建的镜像，通过
点击run按钮，输入container name（容器名称）,host port服务器端口号，container port容器端口号,即可在container页面里创建一个容器
42、redis里的数据一般不保留，也就是删除容器redis，里面的数据会丢失。如果需要保留，docker run -d --name redis -p 6379:6379 -v redis_data:/data redis:7-alpine，-v redis_data:/data把容器的/data目录挂载到docker的redis_data卷，如果容器删除了，再新创建一个容器挂载同一个卷就能恢复数据，-v是挂载数据卷，是--volume的缩写
